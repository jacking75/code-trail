# 첫 분석과 공유

언어 서버를 준비하기 전에는 저장소에 포함된 예제부터 읽을 수 있다.

```powershell
npm run build
node packages/cli/dist/main.js --read-share examples/first-review.ctshare.json
```

브라우저가 열리면 `분석 기록`에서 목표, 열린 질문, 안내 순서를 확인한다.
안내 순서의 `따라 읽기`를 누르면 화면 아래 막대가 뜨고 `다음`만 눌러 끝까지 읽는다
(`[` · `]` · `Esc`). 이 실행은 임시 디렉터리의 읽기 전용 복사본만 사용하며 예제 파일이나
다른 프로젝트를 바꾸지 않는다.

자기 프로젝트에서는 다음 순서로 첫 자료를 만든다.

1. `npm run start -- <프로젝트 경로>`로 연다.
2. 무엇을 볼지 정한다. 변경 목록 머리의 **변경 기준**에서 `<브랜치> ← 갈라진 지점부터`를
   고르면 그 브랜치가 바꾼 것 전부가 시작점이 된다. 커밋한 뒤에도 목록이 비지 않는다.
3. hunk 줄을 눌러 그 자리를 열고, 함수 안에서 `Ctrl+Alt+T`를 눌러 첫 루트를 만든다.
   읽은 hunk 는 줄 오른쪽 `☐`로, 다 본 함수는 노드 헤더의 `☐`(키 `v`)로 표시한다.
4. 기록은 코드를 드래그해 뜨는 선택 칩의 `＋ 기록`으로 남긴다 — 탭이 바뀌지 않고 오른쪽에
   기록 열이 열린다. 노드 헤더의 `＋`나 `분석 기록` 탭에서도 같은 일을 한다.
5. 설명할 순서를 만든다. `현재 기록 순서로 만들기`로 초안을 잡고, 노드 메뉴의
   `안내 순서에 추가`로 단계를 더하고, `✎`로 제목과 설명을 다듬는다.
6. `공유 내용 확인`에서 코드 포함 여부와 건수를 확인한다.
7. 공유 묶음, Markdown, 정적 HTML 중 수신자 환경에 맞는 형식을 내려받는다.
   트레일 툴바의 `Markdown`은 `기록 포함`·`Mermaid 포함`을 고를 수 있고, 함수 하나만
   필요하면 노드 메뉴의 `Markdown 복사`로 그 서브트리만 가져간다.

파일이 바뀌면 기록 위치는 몇 초 안에 **자동으로** 다시 판정된다. 자리만 옮겨졌으면 조용히
따라가고, 후보가 여럿이거나 대상이 사라졌을 때만 알린다 — 재연결은 사람이 한다.
`위치 다시 확인`으로 언제든 직접 돌릴 수도 있다. `확인함`이었던 범위나 노드의 코드가
바뀌면 `재검토`로 내려가며, 같은 본문 후보가 여러 곳이면 자동으로 하나를 고르지 않는다.
