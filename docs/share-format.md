# 공유 묶음 형식

공유 파일은 UTF-8 JSON이며 `format: "code-trail-share"`, `schemaVersion: 1`을 가진다.
확장자는 `.ctshare.json`을 권장한다. 수신자는 전체 파일 크기, 런타임 스키마, ID 중복,
트리 깊이, 모든 개체 참조와 `integrity` SHA-256을 통과한 뒤에만 가져온다.

`integrity`는 그 필드만 제외한 객체를 키 정렬 정규 JSON으로 직렬화해 계산한다. 배열 순서는
의미가 있으므로 바꾸지 않는다. 가져올 때 트레일·노드·기록·작성자·기준 ID를 새 UUID로
바꾸며 원본 파일을 덮어쓰지 않는다.

`lineage`는 최초 분석 ID, 송신 기준 내용 해시, 바로 전 묶음 ID를 담고 `mergeBase`는 송신
당시 기록·답글을 담는다. 가져온 복사본을 다시 내보낼 때 로컬 ID를 원래 ID로 되돌려 세 방향
비교가 가능하게 한다. 병합 범위는 기록과 답글뿐이며 트레일 구조·보드 배치는 각 복사본에
남긴다. 충돌한 양쪽 본문은 어느 하나를 자동 선택하지 않는다.

안내 단계는 `annotationId`로 연결된 기록을 명시한다. 화면과 정적 HTML의 내부 참조는
묶음·분석·안내 순서·단계 또는 기록 ID를 담으며 세션 토큰이나 로컬 파일 경로를 담지 않는다.

## 포함 정책

- `includeCode` 기본값은 `false`다. 꺼져 있으면 노드 본문, 선택 문자열, 앞뒤 문맥을 비운다.
- 외부 심볼은 절대경로 대신 `[프로젝트 외부]`로 쓴다.
- 작성자와 답글, 의도적으로 보여줄 보드 배치는 각각 선택할 수 있다.
- 실행 설정, 환경 변수, 세션 토큰, `documentId`, 로그, 삭제 이력, 개인 초안은 넣지 않는다.
- 로컬 AI endpoint·모델 설정과 채택 전 AI 초안은 넣지 않는다.
- 자유 입력 본문은 자동 비밀 제거를 보증하지 않으므로 미리보기 경고 뒤 사용자가 확인한다.
- 검토 기록(`reviews`)은 대상과 함께 실린다. 범위 대상(`{"kind":"range","anchorId":…}`)뿐
  아니라 **노드 대상**(`{"kind":"node","trailId":…,"nodeId":…}`)도 들어간다 — 받는 쪽에서
  "이 함수는 봤다" 가 그대로 보인다. 기준은 그 노드가 보여주던 파일의 내용 해시다.

현재 상한은 파일 32MiB, 업로드 청크 256KiB, 트리 깊이 128, 분석 개체 10,000개다.
상위 `schemaVersion`은 기본값으로 덮어쓰거나 부분 복원하지 않고 거부한다.

## Markdown 과 정적 HTML

Markdown 은 **트레일 Markdown 과 같은 함수**가 만든다(`shared/domain/markdown.ts`).
어디서 내보내도 같은 형식이다 — 깊이는 제목 수준, 형제에는 순번(①②③), 진입 링크와
`경로:줄`, 노드별 기록은 코드 블록 바로 뒤 인용으로, `확인함` 검토는 헤더 배지로 붙는다.
기록 본문은 Markdown 으로 해석하지 않는다(`&`·`<`·`>` 이스케이프).
`Mermaid 포함` 을 고르면 맨 앞에 `flowchart TD` 블록이 붙고, 재귀 노드는 점선 화살표다.

정적 HTML 의 코드도 **트리 구조를 지킨다** — `<details>` 를 깊이대로 중첩하고 자식에
순번을 단다. 평평하게 늘어놓으면 "무엇에서 무엇으로 들어갔는지" 가 사라져 코드 조각
목록이 된다. 안내 순서의 각 단계에는 이전·다음 앵커가 있어 스크립트 없이도 따라 읽는다.
CSP 와 "외부 통신 없음" 은 그대로이고 스크립트를 넣지 않는다.

예제는 [`examples/first-review.ctshare.json`](../examples/first-review.ctshare.json)이다.
