# 코드 이해·공유 사용성 평가

이 문서는 T33과 T40의 실제 사용자 평가 절차와 아직 확보하지 못한 증거를 구분한다.
자동 시험과 구현자가 수행한 화면 검증은 제품 회귀 근거지만 실제 사용자 관찰을 대신하지 않는다.

## 평가 과제

참여자는 자신의 업무 저장소 사본이나 공개 예제에서 다음 과제를 수행한다.

1. 설치 후 진단 화면에서 준비 상태와 다음 행동을 설명한다.
2. 변경 목록에서 읽기 시작점을 고르고 함수 흐름을 트레일로 만든다.
3. 설명·질문·우려를 코드 범위에 남기고 검토 상태와 근거를 구분한다.
4. 코드 미포함 공유 묶음을 보내고, 수신자는 프로젝트 없이 안내 순서대로 읽는다.
5. 같은 프로젝트를 연결해 코드 버전 일치 여부를 확인하고 답글을 회신한다.
6. 원 작성자는 회신의 추가·수정·삭제 또는 충돌을 확인하고 합친다.

각 과제는 완료 시간, 도움을 요청한 지점, 잘못 이해한 상태, 데이터 손실 여부, 근거로
되돌아간 성공 여부를 기록한다. 표시 이름과 저장소 내용은 수집하지 않고 관찰 기록은
참여자를 식별할 수 없게 요약한다.

## 현재 확보한 비사용자 근거

- Windows x64 / Node 22.17.1 / Chrome에서 빌드, 타입 검사, 단위·통합·브라우저·배포 설치 시험을 수행한다.
- 1,000개 노드와 100·1,000·10,000개 분석 기록 성능은 [`perf-1000-nodes.md`](perf-1000-nodes.md)에 기록한다.
- 1500×950과 850×900 화면에서 분석 기록 보조 열, 단일 열 전환, 가로 오버플로와 콘솔 오류를 확인한다.
- 실제 언어 서버와 실제 Ollama는 이 기계에 없어 가짜 서버·가짜 제공자 시험과 공식 API 계약만 확인한다.

## 미완료 상태와 다음 결정

T33은 실제 참여자 관찰이 없으므로 완료로 표시하지 않는다. T40도 같은 과제의 배포 전후
비교값이 없어 완료로 표시하지 않는다. 참여자와 사용할 저장소 범위가 정해지면 위 표의
빈 값을 채우고, 가장 큰 실패 비용을 기준으로 다음 배포의 우선순위와 완료 조건을 갱신한다.
