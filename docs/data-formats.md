# 데이터 형식과 복구

저장 배치·복구와 공유 묶음 형식을 한 파일에 둔다.

## 데이터 배치와 복구

`.code-trail/` 아래의 의미 데이터와 개인 데이터를 분리한다.

```text
.code-trail/
  settings.json                 공유 가능한 UI·언어 사용·상대 솔루션 설정
  index.json                    트레일 목록 캐시
  trails/<trail-id>.json        트레일 정본
  analysis/<analysis-id>.json   분석 기록 정본
  snapshots/                    불변 코드 기준 자료
  local/settings.json           에디터·언어 서버 실행 값·작성자·로컬 AI 제공자
  local/ui-state.json           개인 화면 상태 — 사이드바·기록 열·탭·마지막 문서·이동 이력·변경 기준
  local/drafts/                 저장 전 개인 초안
  runtime/                      잠금·언어 서버 로그
```

`local/`과 `runtime/`은 자체 `.gitignore`를 가지며 프로젝트 루트 `.gitignore`는 바꾸지 않는다.

**개인 화면 상태는 `localStorage` 가 아니라 여기 있다.** 브라우저 origin 이
`127.0.0.1:<포트>` 이고 포트 기본값이 0(운영체제가 고른다)이라, `localStorage` 에 넣은 값은
서버를 다시 띄울 때마다 다른 origin 이 되어 사라진다. 이 파일은 **절대경로·`documentId`·
세션 토큰을 담지 않는다** — 담기는 것은 스키마(`localUiStateSchema`)가 정한 값뿐이고,
파일이 손상되면 조용히 버린다(복구 후보로 올리지 않는다). 공유 읽기 모드(`--read-share`)는
임시 디렉터리에서 돌므로 아예 쓰지 않는다.
트레일의 보드 좌표·활성 노드 같은 화면 상태는 기존 호환성을 위해 트레일 파일에 남아 있다.
분석 기록 공유 직렬화는 이 화면 상태를 기본 제외하며, 보드 배치를 의도적으로 포함할 때만 넣는다.

정본은 같은 디렉터리의 임시 파일에 쓴 뒤 원자적으로 교체한다. 분석 정본을 바꾸기 전에는
`.bak`을 남기고 교체 뒤 다시 읽어 스키마와 revision을 확인한다. 시작할 때 더 새 임시 파일이나
백업을 발견하면 진단 화면의 복구 후보로 올리며, 알 수 없는 버전을 빈 문서로 덮어쓰지 않는다.

1.0의 단일 `settings.json`을 처음 읽으면 `.pre-local-settings.bak`을 만든다. 실행 파일·인자·
환경 변수·초기화 옵션·에디터 설정은 `local/settings.json`으로 옮기고 공유 파일에는 안전한
값만 남긴다. 이전이 의심스러우면 서버를 끈 뒤 두 파일과 백업을 비교하고 백업 사본을 별도
보관한다. 기존 Git 이력에 들어간 비밀값은 이 이전으로 삭제되지 않으므로 별도로 회전·제거한다.

분석 기록의 이력에는 사람이 한 일 말고 **시스템이 한 일**도 남는다. 파일이 바뀌어
자동으로 기록 위치를 다시 판정하면 그 항목의 `actorId` 가
`00000000-0000-4000-8000-000000000000`(시스템)이다. 재확인이 언제 돌았는지 모르면
"누가 상태를 바꿨나" 를 답할 수 없기 때문이다. 재연결(`anchor.rebind`)은 여전히 사람의
항목으로 남는다.

AI 제공자 endpoint·모델·사용량 제한도 로컬 설정에만 둔다. 공유 묶음과 프로젝트 설정에는
들어가지 않는다. 현재 endpoint는 loopback origin만 허용하며 비밀키 필드는 제공하지 않는다.

## 공유 묶음 형식

공유 파일은 UTF-8 JSON이며 `format: "code-trail-share"`, `schemaVersion: 1`을 가진다.
확장자는 `.ctshare.json`을 권장한다. 수신자는 전체 파일 크기, 런타임 스키마, ID 중복,
트리 깊이, 모든 개체 참조와 `integrity` SHA-256을 통과한 뒤에만 가져온다.

`integrity`는 그 필드만 제외한 객체를 키 정렬 정규 JSON으로 직렬화해 계산한다. 배열 순서는
의미가 있으므로 바꾸지 않는다. 가져올 때 트레일·노드·기록·작성자·기준 ID를 새 UUID로
바꾸며 원본 파일을 덮어쓰지 않는다.

`lineage`는 최초 분석 ID, 송신 기준 내용 해시, 바로 전 묶음 ID를 담고 `mergeBase`는 송신
당시 기록·답글을 담는다. 가져온 복사본을 다시 내보낼 때 로컬 ID를 원래 ID로 되돌려 세 방향
비교가 가능하게 한다. 병합 범위는 기록과 답글뿐이며 트레일 구조·보드 배치는 각 복사본에
남긴다. 충돌한 양쪽 본문은 어느 하나를 자동 선택하지 않는다.

안내 단계는 `annotationId`로 연결된 기록을 명시한다. 화면과 정적 HTML의 내부 참조는
묶음·분석·안내 순서·단계 또는 기록 ID를 담으며 세션 토큰이나 로컬 파일 경로를 담지 않는다.

### 포함 정책

- `includeCode` 기본값은 `false`다. 꺼져 있으면 노드 본문, 선택 문자열, 앞뒤 문맥을 비운다.
- 외부 심볼은 절대경로 대신 `[프로젝트 외부]`로 쓴다.
- 작성자와 답글, 의도적으로 보여줄 보드 배치는 각각 선택할 수 있다.
- 실행 설정, 환경 변수, 세션 토큰, `documentId`, 로그, 삭제 이력, 개인 초안은 넣지 않는다.
- 로컬 AI endpoint·모델 설정과 채택 전 AI 초안은 넣지 않는다.
- 자유 입력 본문은 자동 비밀 제거를 보증하지 않으므로 미리보기 경고 뒤 사용자가 확인한다.
- 검토 기록(`reviews`)은 대상과 함께 실린다. 범위 대상(`{"kind":"range","anchorId":…}`)뿐
  아니라 **노드 대상**(`{"kind":"node","trailId":…,"nodeId":…}`)도 들어간다 — 받는 쪽에서
  "이 함수는 봤다" 가 그대로 보인다. 기준은 그 노드가 보여주던 파일의 내용 해시다.

현재 상한은 파일 32MiB, 업로드 청크 256KiB, 트리 깊이 128, 분석 개체 10,000개다.
상위 `schemaVersion`은 기본값으로 덮어쓰거나 부분 복원하지 않고 거부한다.

### Markdown 과 정적 HTML

Markdown 은 **트레일 Markdown 과 같은 함수**가 만든다(`shared/domain/markdown.ts`).
어디서 내보내도 같은 형식이다 — 깊이는 제목 수준, 형제에는 순번(①②③), 진입 링크와
`경로:줄`, 노드별 기록은 코드 블록 바로 뒤 인용으로, `확인함` 검토는 헤더 배지로 붙는다.
기록 본문은 Markdown 으로 해석하지 않는다(`&`·`<`·`>` 이스케이프).
`Mermaid 포함` 을 고르면 맨 앞에 `flowchart TD` 블록이 붙고, 재귀 노드는 점선 화살표다.

정적 HTML 의 코드도 **트리 구조를 지킨다** — `<details>` 를 깊이대로 중첩하고 자식에
순번을 단다. 평평하게 늘어놓으면 "무엇에서 무엇으로 들어갔는지" 가 사라져 코드 조각
목록이 된다. 안내 순서의 각 단계에는 이전·다음 앵커가 있어 스크립트 없이도 따라 읽는다.
CSP 와 "외부 통신 없음" 은 그대로이고 스크립트를 넣지 않는다.

예제는 [`examples/first-review.ctshare.json`](../examples/first-review.ctshare.json)이다.
